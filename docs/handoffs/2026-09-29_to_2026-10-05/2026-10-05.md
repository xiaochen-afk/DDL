### P0 平台本地通知适配（代码完成，真机验收待办）

- 实际完成：新增 `FlutterNotificationPort`，通过 `flutter_local_notifications` 接入 Android/iOS 本地通知，读取通知与 Android 精确闹钟权限，用户主动申请权限，精确权限缺失时改用非精确排程，提供系统通知设置入口；创建普通/紧急 Android 渠道，通知正文使用不含任务标题和备注的通用文案，点按 payload 仅含任务 ID。冷启动和应用运行中点按均可打开对应任务详情。
- 新增 `PlatformReminderCoordinator`：以 SQLite 提醒记录为期望，以平台待处理 ID 为实际状态，按稳定正整数 ID 差异排程/取消；无权限记录 `NOTIFICATION_PERMISSION_DENIED`，平台失败记录 `NOTIFICATION_SCHEDULE_FAILED`，后续协调重试。Android 待处理上限 120、iOS 预留限制只排最近 60 条；应用启动、恢复前台、任务与偏好变化时滚动补充。设备 IANA 时区自动同步至偏好，变化时强制重排。
- Android 清单新增 `POST_NOTIFICATIONS`、`RECEIVE_BOOT_COMPLETED`、`SCHEDULE_EXACT_ALARM` 及插件排程/重启接收器；Gradle 开启 core library desugaring。iOS `AppDelegate` 设置 `UNUserNotificationCenter` delegate，初始化时不自动请求通知权限。个人中心展示授权、非精确降级和 vivo/OPPO 后台耗电限制提示；首页旧的“系统通知尚未接入”文案已更新。
- 关键设计：SQLite `PENDING` 只是期望计划，`SCHEDULED` 只表示平台排程调用成功或待处理 ID 存在，均不保证送达。任务操作即使平台通知失败也能继续；通知权限仅在用户主动开启或点击“申请权限”时请求。Android 精确提醒使用 `SCHEDULE_EXACT_ALARM`，未使用商店审核要求更严格的 `USE_EXACT_ALARM`。
